# 技术融合决策记录 (Decision Log)

## 核心工程决策

### 1. 为什么新建 week5 独立根目录而不在旧项目追加？
- **决策**：新建 `week5-agent/` 独立应用层。
- **原因**：保证旧资产（week2-4）只读，职责分离，风险隔离；避免新旧代码耦合，防止 RAG 检索测试受 Agent 逻辑干扰。
- **失效条件**：如果未来需要合并为单一部署包，且资源极度受限，可重新评估。

### 2. 为什么用 Adapter 封装而不是直接 import 旧代码？
- **决策**：旧项目作为“资产库”，新项目通过明确契约（HTTP/CLI/薄函数）调用。
- **原因**：避免 week2-4 的内部复杂依赖污染 week5 环境。抽取重写优于直接复制。
- **失效条件**：旧 API 已是稳定独立服务且契约清晰时，可改为 HTTP 调用，但仍不复制框架配置。

## 核心设计原则（面试/答辩防身指南）

1. **为什么用独立 Registry 而非简单的 tools 数组？**
   - 失效条件：单文件 Demo 确实不需要 Registry。但当工具数量达到 20+，如果没有双层字典（名称+版本）做冲突检测和权限投影，整个系统会立刻失控。
2. **为什么 Schema 校验必须在模型输出后、执行前？**
   - 失效条件：若模型侧已具备极强的原生强约束且工具毫无副作用，可简化。但企业级写操作（增删改）绝对不能省，这是安全底线。
3. **为什么 RAG 检索链路必须降级为 Adapter 薄工具？**
   - 失效条件：本周主线是 Agent 工程治理。如果 KPI 明确变成“检索质量评估”，应另立项目，绝不混入 Agent 治理，防止“缝合怪”。
4. **为什么对话状态、RAGAS、BM25/RRF 一律舍弃或降级？**
   - 失效条件：若下周任务明确要求多轮 Agent 或检索评估，应拆分为独立的周任务重新设计，而不是直接塞入本周已经稳定的核心链路。

# Day 4 决策记录：幂等键与人工审批

## 1. 幂等键由谁生成？
- **决策**：由确定性系统生成，包含“租户/用户 + 任务 ID + 工具名 + 规范化参数哈希”。
- **为什么不能交给模型？** 模型是概率性的，可能幻觉、换写法或跨租户撞键，导致同一请求生成不同键，幂等保护失效。
- **失效条件**：幂等键丢失（无法识别重复）或跨租户复用（数据泄露或误拒）。因此必须存入指纹并在执行前比对。

## 2. 写操作超时后为什么不能直接重试？
- **决策**：写操作 `retryable=False`、`retry_max=0`；如必须重发，先查真实状态或使用幂等键 + 补偿。
- **为什么不能直接重试？** 超时只是“没等到结果”，不代表“没发生”。下游可能已经执行完毕，自动重试会导致第二次副作用。
- **失效条件**：如果下游不支持查询状态，且没有幂等键，只能阻断写操作，等待人工核对。

## 3. 为什么副作用工具走 Human-in-the-loop（人工审批）？
- **决策**：副作用工具 `/run` 时 100% 拦截，进入 `pending`；`/approve` 后才 Resume。
- **为什么？** 写操作不可逆，模型可能误判直接触发。必须在服务端硬拦截，不能依赖模型自觉。
- **失效条件**：高频低风险写操作会被审批拖垮。此时应改为“幂等键 + 事后审计”，而不是无脑全审批。

## 4. 审批后 Resume 的状态如何保证不重复执行？
- **决策**：状态机（只有 `pending` 才能执行）+ 幂等记录（用拦截时的键查重）。
- **为什么？** 状态机防止同一审批单被反复点；幂等记录防止同一业务请求换审批单重来。
- **失效条件**：状态持久化丢失（如进程重启）时，需依赖幂等键兜底；若幂等记录也丢失，需补偿或人工核对。

## 5. 补偿与幂等重放的边界是什么？
- **决策**：幂等重放是“阻止第二次发生”；补偿是“已经发生了，尝试撤销或修正”。
- **失效条件**：下游不支持补偿（如消息已发出、钱已到账），此时应阻断写操作，禁止强推。

## Day 5：四层归因的失效条件

- 当前四层归因（工具选择 / 参数生成 / 工具返回 / 忽略返回）适用于单 Agent 调用工具的场景。
- 失效条件 1：多 Agent 协作时，错误可能发生在“Agent 间交接”层，例如上游 Agent 输出格式、语义、权限不符合下游 Agent 预期。扩展动作：增加“Agent 间交接”层，记录交接协议、字段映射、权限边界；否则会把交接错误误判为工具选择错误或参数生成错误。
- 失效条件 2：遇到高危操作（如删除、转账）时，仅靠工具调用日志无法覆盖安全边界，需要在工具选择层强制加入审批拦截。
- 触发信号：日志中出现多个 Agent 角色、交接消息、或跨 Agent 的 schema 映射失败；或高危工具参数通过未触发 `is_approval` 记录。
